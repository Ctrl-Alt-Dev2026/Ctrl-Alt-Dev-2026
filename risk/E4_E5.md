# E4 / E5 și integrarea accidentelor reale

## Rulare acum, integral sintetică

```powershell
python -m pip install -r risk/requirements.txt
python -m risk.run --input false_data --mode synthetic --output risk/output/e4-e5-demo
python -m unittest risk.test_statistics_h3 -v
```

H3 4.5.0 a fost instalat și verificat în mediul curent. Cerințele sunt într-un
fișier propriu ariei risk; requirements-urile comune nu au fost modificate.
Nu se fac cereri OSM în timpul analizei. Output-ul trebuie să fie un director
nou; nu se suprascriu datele colegilor sau un export anterior.

Rezultatul pe fixture-urile actuale: 17 evenimente unice, 14 eligibile, 8 celule
H3 la rezoluția 9, 6 locații cu asocieri provizorii și 3 hotspot-uri cu minimum
două evenimente (scoruri 12, 8, 5). Patru evenimente precise au incompatibilitate
trecere/intersecție și rămân neasociate unei locații. Datele false originale și
scorurile de referință 13,11,6,5,5 nu sunt rescrise.

## Output

| Fișier | Conținut |
|---|---|
| hotspots.json | Contractul existent, inclusiv pe_ore și h3 completat pentru coordonata locației |
| location_statistics.json | Statistici E4 pentru fiecare locație asociată, inclusiv cele cu un singur eveniment |
| accidents_h3.geojson | Poligoane H3, rezoluția 9, evenimente unice și numărători pentru coloanele frontend-ului |
| analysis_report.json | Excluderi, ambiguități, totaluri, politică de selecție și amprente SHA-256 ale intrărilor |

Statisticile includ 24 de valori pe_ore, ora_necunoscuta, noapte, zi, necunoscut,
cauze raportate și distribuția gravității. O oră null nu devine 00:00. Noaptea
nu este dedusă din ora calendaristică: se păstrează true/false/null din accident.
O cauză relatată nu devine verdictul nostru. Duplicate identice se numără o
singură dată; duplicate contradictorii opresc rularea cu eroare explicită.

Verificări de consistență: suma celor 24 de ore + ore necunoscute = evenimente;
zi + noapte + necunoscut = evenimente; suma cauzelor = evenimente. Ora invalidă,
coordonatele precise invalide și tipurile incorecte nu sunt reparate prin invenție.

H3 este o grilă geografică pentru vizualizare. Celulele grupează coordonatele
accidentelor eligibile, inclusiv pe cele neasociate/ambigue față de treceri.
Hotspot-urile grupează numai asocierile provizorii acceptate. De aceea totalul
H3 (14) nu trebuie să fie egal cu evenimentele din hotspot-uri (7). Numărul
accidentelor dintr-o celulă poate fi folosit de frontend pentru înălțimea coloanei;
nu se însumează bonusuri de infrastructură și nu se calculează scor nou pe celulă.

Coordonatele de intrare H3 sunt latitudine,longitudine; exportul GeoJSON le
inversează la longitudine,latitudine și închide inelul poligonului.
API folosit: https://uber.github.io/h3-py/api_quick.html .

## Când vin accidentele reale

Persoana 3/integratorul furnizează un director cu manifest.json (schema_version
2.0, data_mode observed) și accidents.json conform contractului. Nu modificăm
aceste fișiere. Se folosesc contextul OSM și limita municipală deja verificate:

```powershell
python -m risk.run --input data/observed --mode observed --context-dir context/output/observed/iasi --output risk/output/observed-run-01
```

`data/observed` este un exemplu de cale viitoare, nu un set de date real existent.
Runnerul refuză manifestele sintetice în modul observed și trecerile SINTETIC
în locul OSM. Nu folosește scenariul mixt din risk.scenario pentru export observat.

Politica conservatoare a acestui runner pentru observed: numai evenimente
verificat=true, in_iasi=true și precizie trecere/intersectie/segment intră în
calcul. Cele neverificate rămân în raport cu status not_manually_verified.
Coordonatele sunt verificate și împotriva limitei municipiului: un in_iasi=true
contradictoriu cu geometria este exclus și semnalat, fără a modifica valoarea
primită de la Persoana 3. Valorile neclare nu sunt corectate automat.

Asocierea rămâne în 50 m, cu geometrie proiectată în metri. Mai mulți candidați,
incompatibilitățile de tip și evenimentele localizate pe segment necesită review.
Nu sunt forțate asocieri pentru a umple clasamentul. verificat din hotspot
rămâne false, deoarece aprobarea evenimentelor nu confirmă și asocierea la trecere.

Acest runner generează rezultate pentru review local; nu publică în backend
și nu modifică manifest.json sau regulile de recomandări. Problemele de articole
și totaluri din snapshot-ul comun rămân în responsabilitatea integrării/auditului
colegilor, nu sunt mascate prin acest export de analiză.

Testele pentru modul observed folosesc exclusiv date artificiale temporare;
nu există în acest livrabil rezultate observate de accidente reale.
